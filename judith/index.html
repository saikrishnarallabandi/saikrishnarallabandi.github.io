// the shift

An agent for one person is a feature.
An agent for a group is a new social contract.

We can build agents today — a model, a loop, a few tools; you can stand one up this afternoon. Almost every one serves one person. Judith serves a group: it answers in the family thread, remembers across collaborators, and speaks first on the glasses. The moment an agent joins a group, it inherits problems a personal one never had — and trust becomes the whole product.

// the harness — four jobs

Join a group, and the harness takes on four jobs.

The original three are still there — guard, memory, route. The paper makes the fourth unavoidable: verify. Judith has to know which evidence and which validator are good enough before a reply reaches the room.

// project ascent · the architectural rule

One invariant per plugin.

Judith is not one program. She is a model surrounded by 21 plugins, and each one owns exactly one invariant — narrow enough that a regression can be named, tested, and reverted without weakening the rest of the assistant. The payoff the rule claims is attribution: a user-visible failure should resolve to a decision at a named stage, not to "the model did not answer."

Ascent is the control plane, not the runtime. The thing that loads a plugin and calls it is the OpenClaw gateway. Ascent holds the source, deploys it with a checksum manifest, checks for drift every 30 minutes, and measures what each plugin did.

// the contract

A plugin is a manifest and a register function.

The manifest is read without executing plugin code, so the gateway can validate configuration and discover tool ownership before it loads anything. A missing or invalid manifest is a plugin error, not a warning.

// plugins/disha/openclaw.plugin.json — abridged
{
  "id": "disha",
  "name": "Disha Model Router",
  "kind": "routing",
  "activation": { "onStartup": true },
  "contracts": { "tools": ["disha_route", "disha_gate", "disha_state"] },
  "configSchema": {
    "type": "object",
    "additionalProperties": false,
    "properties": { "enabled": { "type": "boolean", "default": true } }
  }
}

Two field semantics that bite. additionalProperties: false means one unrecognised config key rejects the entire config reload — the plugin keeps running on its old config, silently. And kind is not a taxonomy: only memory and context-engine claim a real exclusive slot. Eleven manifests carry decorative values that do nothing.

The module exports register(api). Everything a plugin can do, it does through that one object: attach a lifecycle hook, register a tool, read its own config, log.

module.exports = {
  id: "disha",
  name: "Disha Model Router",
  register,
  activate: register,   // beta removed `activate`; export both to load on stable and beta
};

The sharpest trap in the whole system: api.on() and api.registerHook() are different registries with misleading names. Only api.on() is invoked by the conversation path. Register with the wrong one and the plugin loads, reports no diagnostics, shows up in plugins inspect — and is never called.

// seven behavioural kinds

What a plugin is allowed to do
is decided by which hook it takes.

The manifest's kind field is decorative. The kinds that matter are behavioural — derived from what each plugin actually registers.

kind 01

Context injection

situation · avastha · state-injector · heartbeat-focus

Take before_prompt_build, return { prependContext }. The whole contract is a return value. Note what this example does not do: a stale digest returns nothing rather than a lie, an unidentifiable turn injects nothing rather than guessing, and the live wake path never throws.

api.on("before_prompt_build", async (_event, ctx) => {
  try {
    // LIT-179: gate on the PERSON, not ctx.agentId. Once the per-person
    // bindings collapsed into one agent, agentId became a constant
    // and this gate passed for EVERY DM.
    if (!isOwnerTurn(ctx, { rosterPath: cfg.rosterPath, expect: ownerAgentId })) return undefined;
    if (isSharedOrPublicCtx(ctx)) return undefined;
    const block = readSituationBlock(filePath, staleMs, Date.now());
    if (!block) return undefined;
    return { prependContext: block };
  } catch (_) {
    return undefined; // live wake path: never throw
  }
});

kind 02

Gate / enforcement

jataayu + 7 submodules

Return a decision. { outcome: "block" } stops the turn; anything else passes. The guard fails open on every fault — a defect in a guard must not be able to stop Judith from answering.

if (r.risk === "HIGH" && blockOnInboundHigh) {
  return {
    outcome: "block",
    reason: `jataayu: HIGH prompt-injection risk — ${r.reason}`,
    message: "Blocked by the Jataayu security guard: this content" +
             " looks like a prompt-injection attempt.",
    category: "prompt-injection",
  };
}
return { outcome: "pass" };
} catch (_e) {
  console.error(`[jataayu-gate] error fail-open: ${_e.message}`);
  return { outcome: "pass" };
}
}, { priority: 100 });

plugins/jataayu/index.js:594–607

The owner bypass reads sender fields only, never message content. Content is attacker-controlled: any external sender could paste the owner's name or number into a message and inherit a never-block bypass. The effect boundary is blunter still — it maps each tool to the effect it really has, because the library resolves unknown tools to read, which allows. apply_patch resolved to read though it writes files; smriti_remember resolved to read though it writes memory.

kind 03

Tool

disha · gmail · health · sangraha · maestro · upaya · keenable-search · linkedin-connector

Register a tool, keep no policy in JavaScript. The Node module is a wire adapter that shells out to a Python core, so the CLI, cron, the tests, and the plugin all consume one implementation of the rule.

api.registerTool({
  name: "disha_route",
  description: "Resolve a task shape to the Ascent-owned provider/model choice.",
  parameters: { type: "object", additionalProperties: false,
                required: ["shape"], properties: { /* … */ } },
  async execute(_toolCallId, params) {   // POSITIONAL — params is the 2nd arg
    const args = ["resolve", String(params.shape), "--json"];
    return toolResult(parseJson(await runRoute(cfg, args)));
  },
});

plugins/disha/index.js:76–107

Both details in that signature were real outages. Reading the first argument as the params object binds it to the tool-call id string — so a security guard scanned "" and returned an unconditional "safe". And execute must resolve to {content:[…], details}; a bare object lands as content: undefined and dies in the provider layer. That one broke every Gmail search.

kind 04

Observer

sakshi · lane-watchdog · inbound-ledger

Take hooks, return nothing, write a ledger. Observers are why attribution works at all: per-tool failure rates only separate because someone wrote the row. Where a plugin emits no ledger, its invariant is unfalsifiable.

kind 05

Router / delegation

sarathi disabled

Claim a turn and re-dispatch it to a sub-session. Registered at priority 10 — deliberately low, so the security gates at 100 settle first. Hooks are first-claim-wins, so a prompt Jataayu would block must never reach the delegator.

kind 06

HTTP surface

drishti

Register a route under gateway auth instead of a tool. Drishti is the jobs board — every run, why it failed, and a re-run button.

kind 07

Memory plane

smriti

The one kind that claims a real exclusive manifest slot. Atomic facts with provenance, superseding, and quarantine: 6,175 memories, 1,093 lineage edges, 13 namespaces. Formation runs on agent_end.

a load-order quirk worth knowing

Five plugins register a tool they do not need.

A hooks-only plugin historically never appeared in the gateway's loaded set. So situation, avastha, state-injector, heartbeat-focus, and sakshi each expose a read-only inspection tool purely to make the load deterministic. The injection is the hook, not the tool. Two plugins — the WhatsApp identity and surface-contract pair — register zero tools and declare contracts.hooks instead, and load fine, so the workaround is not universally required.

// what the decomposition did not buy

The rule pays off where a plugin writes a ledger.
It fails in three ways I did not anticipate.

Where a plugin records what it did, attribution is real: per-tool failure rates separate from 0.0% over 22,310 exec calls to 42.0% over 348 browser calls, against a 2.12% tool aggregate that describes no actual component. Last-mile rewrites localised 65 structural leaks — 44 raw JSON, 21 internal metadata — that would otherwise have reached a human channel. The failures are the more useful result.

failure 01

Isolating an invariant does not deploy it.

Jataayu's effect boundary is designed, implemented, and running — in shadow. All 544 effect events are shadow-mode. The guarantee the architecture advertises is not the one in force.

failure 02

It does not keep it alive.

A component can pass its tests while inert. Disha is byte-clean on disk and absent from every load gate, so the drift verifier reports it healthy while the gateway ignores it entirely.

failure 03

It does not measure it.

Several plugins emit no telemetry at all. Their invariants cannot be falsified, which means the architecture cannot tell you whether they ever held.

Numbers from 57 days of execution traces (77,919 spans), 37 closed self-improvement cycles, 2,026 proactive messages, a 6,175-fact memory store, and 21 plugins of which 19 are loaded. Every figure is re-derivable from the live stores with one command.

// semalign · research framing

The next problem is not “does the agent answer?”
It is “which validator should be trusted here?”

PROBE decomposes hallucination detection into claim decomposition, evidence finding, evidence evaluation, and localization. FRANQ separates factuality from faithfulness to retrieved evidence. EAEV, HaMI, HalluGuard, and related work show that detectors specialize. RouteGuard adds the warning: complementarity is not enough unless routing realizes the gain.

Judith becomes the system under test.

Project Ascent turns the plugin stack into a measurable assurance loop: every risky answer is evidence, every validator has a failure profile, and escalation is a policy decision rather than a vibe.

decomposeBreak answers into claims before judging the whole response.
retrieveScore whether the right evidence was found, not only whether a judge sounded confident.
specializeRoute entity, temporal, numerical, citation, and semantic-drift risks to the validator that actually sees them.
measureTrack overlap, conditional recovery, oracle upper bound, realized router gain, cost, latency, and label-noise sensitivity.

The research bet.

SemAlign's opening is structured error specialization across heterogeneous validators. The contribution is not “one more hallucination detector”; it is the specialization matrix, conditional-recovery map, and cost-aware router that turns a fleet of imperfect validators into a reliable group-agent harness.
